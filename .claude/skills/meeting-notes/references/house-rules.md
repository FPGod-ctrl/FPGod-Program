# Initial Meeting Notes: house rules by field and section

Source: the firm's house-style README for the initial meeting build, derived from Tristan's own edits of generated drafts (SEP02, SEP10, SEP14). Where the SEP10 and SEP14 rules overlap, SEP14 wins, and this file already applies that. The summary of his edits: **the draft is too wordy, too self-referential, and strays into advice.** Aim shorter and more declarative, keep the reasoning out, and stop at the client's circumstances.

## §A. Header block

| Field | Format | Example (fictional) |
|---|---|---|
| `Name` | Full name | `[CLIENT_1_FIRST] [CLIENT_1_LAST]` |
| `DOB` | `dd/mm/yyyy` | `05/06/1982` |
| `Address` | Street, then **suburb in capitals**, state, postcode. No commas. | `12 Example Street EXAMPLEVILLE VIC 3000` |
| `Mobile` | As given | `TBC` if not said |
| `Email` | As given | `TBC` if not said |
| `Smoker` | `N` or `Y` | `N` |
| `Sex` | As given | |
| `Speciality` | Industry, en dash, job title | `IT – Solutions Analyst` |
| `Employer/self` | Employment basis **and income** | `PAYG $000,000 + Super` |

- Three header lines: Name / DOB / Address; Mobile / Email / Smoker; Sex / Speciality / Employer/self. Each value beside its own label. Check the built header by eye (default, Q-MN-3).
- Fill everything that is known first. Tristan normally fills DOB, mobile, email, postcode, smoker status and the spouse's details from the client file. Read the client file only when Tristan names the folder or asks (default, Q-MN-5). If a value is not in your sources, write `TBC`.
- A long `Employer/self` value moves to its own line. `Sex` and `Speciality` stay on the line above.
- Couple: a `Spouse Details` block directly under the client's, identically formatted, with the same fields. Assume the template has it; if not, add it by hand (default, Q-MN-4).

## §B. Sections

Write each section short and declarative. Delete any section with nothing real in it, heading included; delete by hand any heading the builder leaves behind (default, Q-MN-1).

**Referred from.** Who referred the client, if said. Otherwise delete the section and its heading (default, Q-MN-1).

**About the client.** Age, occupation context, family. For a couple, the children live here (not in Financial circumstances, not under a Family heading). Name the school type where fees are in play ("private school"). Review clients: the same section carries review context.

**What is important to you.** What the money must **do**, not what the client asked. Purpose per cover, short and declarative. This is the section that justifies the sums insured, but it names no sums. Examples of the form:
- "Wants to clear total debt in a claimable Life event."
- "TPD to clear home debt and provide excess monies post tax to fund house modifications or medical expenses."

Delete any education Tristan gave in the meeting.

**Reasons for seeking advice.** Why the client came. For an existing client, a review where the transcript supports it. Scope wording: "life plus TPD and income protection as a minimum".

**Current Insurance.** A structured listing of each policy held: insurer, cover type, amount, owner, inside or outside super, where known. `NOT KNOWN` for an unknown detail inside a listing. Then the standing clause, always written as the last line of the section: `EXISTING COVER REMAINS IN FORCE`, or `EXISTING COVER (IF ANY) REMAINS IN FORCE` when nothing is confirmed (default, Q-MN-11).

**Financial circumstances.** Does **not** repeat the header or About the client: no Income block, no dependants line. It is only:
```
ASSETS
<item> $X
<item> $X
Total $X
LIABILITIES
<item> $X
Total $X
Estimated net position approx. $X.
[NOT CAPTURED line, if any — as its own line, never appended to a sentence]
<one-line driver sentence>
```
Absences: "No investment properties, shares, managed funds, cash or savings have been disclosed."

**Family / partner/ dependants:** single client only. Deleted for a couple, heading included (default, Q-MN-1). Never write invented content under it.

**Super.** Fund, balance, cover inside it, where said. Never "No binding death benefit nominations discussed."

**Estate Planning.** One line of fact (Will, Powers of Attorney, if said). No intestacy explanation.

**Health.** Conditions and facts disclosed. A `TBC` field can carry one qualifying line.

**Height / weight.** As given, or a qualifying line, or delete.

**Hobbies / pets.** Only if discussed. Usually deleted.

**UNDERWRITING.** Only what an underwriter needs: condition, medication and dose, when diagnosed, whether controlled, and the occupation rating still to be established. Nothing about sums insured. A first-contact call usually has nothing to underwrite: delete it.

**Insurance needs.** Never written. Repurposed as UNDERWRITING.

**Goals.** Only if goals were actually explored. Usually deleted on a first-contact call.

**Repeated second block** (`About the client`, `Reasons for seeking advice`, `Existing cover`, `Estate Planning`, `Super`). Always deleted.

**Outcome of meeting.** Deleted whenever no advice was given, even where next steps were agreed. Kept only when the meeting decided to change, cancel, retain or apply for specific cover. Facts only, no action lists (default, Q-MN-7).

## §C. Gaps

- `TBC`, highlighted, in the field it belongs to. Not a sentence, not a closing list.
- Closing `OUTSTANDING - TO BE OBTAINED` list only for a first-contact enquiry where the gaps are too many or too large to sit in fields.
- The older internal rule (gaps as `[CONFIRM]` plus an outstanding list) is retired. `TBC` in the field (default, Q-MN-6).
- `TBC` is this document's house practice for a missing client fact, kept in place of the firm-wide `[ADVISER TO CONFIRM]` (house practice, Q-SH-3).
- Never write "Not disclosed" in this document. A category that is absent or was not raised is "No ... have been disclosed" (default, Q-MN-10).

## §D. What never goes in

Indicative sums insured; premium figures; the super-versus-cash-flow funding split; stepped versus level; the 15% rollover rebate; the deductibility argument; the 70%-of-income basis; anything reading like an argument for a course of action; the intestacy explanation; the "outside the practice's authorisation" disclaimer; meeting education; adviser or client action lists; the service-and-remuneration explanation; anything about the transcript itself.
